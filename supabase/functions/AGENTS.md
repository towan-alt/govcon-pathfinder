# AGENTS.md

## Rules

- The SAM.gov API key lives AES-GCM encrypted (SAMGOV_KEY_ENCRYPTION_SECRET) in `samgov_api_credentials` (service-role only); only the admin-checked `samgov-credentials` function touches it and returns last4/status, never the key. Server code reads it via `_shared/samgov-key.ts` `getSamgovApiKey()`, so the secret never reaches the browser.
- SAM.gov retrieval is manual and step-based: `samgov-fetch` (admin-checked) runs start -> naics (one call per active code, paginated with per-run request cap) -> finish so the page shows real progress; it upserts raw notices into `samgov_opportunities` (unique notice_id, full raw_data) and logs each run in `samgov_fetch_runs`. Both tables are admin-read via RLS, written only by service role.
- Phase 3 rule filtering: `samgov-filter` (admin-checked, step-based start -> batch(200, keyset by id) -> finish) applies `naics_match OR keyword_match` from the live /samgov config tables and writes match reasons + `filter_status` onto `samgov_opportunities`; dry runs only update the `samgov_filter_runs` log. A config hash (`filter_config_version`) aborts runs whose settings change mid-run, and a heartbeat on running runs blocks concurrent processing.
- Full notice descriptions: `samgov-descriptions` (admin-checked, start(mode missing|failed) -> batch -> finish, small concurrency) fetches only validated api.sam.gov noticedesc URLs with no redirects, size/time limits, and stops on 401/429; text goes to `description_text`/`description_status` and is plain text only (never rendered as HTML). The filter treats a pending/failed description as `filter_incomplete`, never `not_matched`, and records the matching field per keyword in `keyword_match_fields`.
- Claude AI fit scoring: `samgov-ai` (admin-checked) stores the Anthropic key AES-GCM encrypted in `samgov_api_credentials` (provider=anthropic), scores only `filter_status = matched` rows via forced tool-use output validated server-side (category derived from score), writes results onto `samgov_opportunities.ai_*`, appends every attempt to `samgov_ai_evaluations`, and runs batches step-wise (batch_start -> batch_step per id -> batch_finish) with a heartbeat lock in `samgov_ai_runs`; unchanged rows are skipped by an input hash of opportunity text + model + profile. Failures only set ai_status/ai_error, never hide records.
- One-click pipeline: `samgov-pipeline` (admin start/status/tick, plus a `cron` tick authenticated by the token in service-only `samgov_pipeline_secret`) advances `samgov_pipeline_runs` fetch -> descriptions -> filter -> ai by calling the existing samgov-* functions with the service-role bearer (accepted by `_shared/samgov-admin.ts`), never duplicating their logic. A lease on the run row stops double processing; `samgov_pipeline_arm()` schedules the 1-minute runner on start and unschedules it when no run is active.
